# Obol 0.4.0

> **Never published on its own.** The 0.4.0 content below shipped in 0.4.5, which is the first release that carries the native offline program. This file is the release record for that cut; the operator upgrade path it documents applies to 0.4.5.

This release replaces the iOS Capacitor shell with a native SwiftUI app that stores finance in SQLite and synchronizes explicitly, adds the same synchronization to desktop local mode, and fixes two defects that blocked deployment and invoice storage. Standalone local use keeps working without a server and without a session.

## Included

- Native SwiftUI iOS app in `app/ios/App`. The Capacitor web view is gone from the iOS target: the shell opens the durable SQLite store behind the Keychain station identity before any feature is shown, and the finance features, formatting and privacy manifest are native. A Keychain or store failure presents a retry instead of creating a second identity or falling back to memory.
- Offline finance on iOS. Every user-visible mutation writes through the local store and the outbox in one transaction, so the app is fully usable with no server, no session and no network. A paired client reads from its local store; projection endpoints such as `GET /api/forecast` and administrative `POST /api/jobs/*` are never sync operations.
- Synchronization per [D016](../decisions/D016-native-offline-sync.md). The desktop station replica in `desktop/electrobun/bun/station-sync.ts` and the iOS engine in `app/ios/App/App/Core/Sync` run the same contract: pairing preview and confirmation, then handshake, complete-commit-group pull, bounded dependency-ordered push, and a second pull. No merge is ever automatic.
- Sync wire contract under [D016](../decisions/D016-native-offline-sync.md): `POST /api/sync/handshake`, `POST /api/sync/push`, `GET /api/sync/pull?cursor=<int>&limit=<1..500>`, plus the one-time `POST /api/sync/seed` and `POST /api/sync/import`. All routes require a D009 session; Bearer is the native transport. `protocolVersion` is 1 with `protocolMin`/`protocolMax` 1, and handshake failures are 409 with a uniform `{ code, message }` body: `CURSOR_NOT_ON_COMMIT_BOUNDARY`, `SERVER_ROLLBACK_DETECTED`, `DATA_EPOCH_CHANGED`, `ENDPOINT_MISMATCH`, `PROTOCOL_UNSUPPORTED`.
- Operations are immutable and idempotent. Each mutation is one envelope with a client-generated UUIDv7 `opId`, a durable per-installation `stationId`, `baseRevisions`, `dependsOn`, and a `payloadHash` over the canonical UTF-8 envelope (`sha256:` plus unpadded base64url). A retry of the same `opId` and hash replays the stored result with no effect; different content for an accepted `opId` is rejected as `OP_ID_REUSED`. Revisions are per entity, and the append-only journal carries deletions as tombstones.
- Pairing with preexisting data is explicit. The wizard distinguishes resume, using server data, importing this device (`POST /api/sync/import`, valid on an empty or populated server, always with fresh ids and a frozen six-field hash), seeding an empty server (the 0.3.0 log-free migration for a database with rows but no operation log), and staying local. Import and seed are bounded at 10 MiB for the complete request and 10,000 financial rows. Destructive branches require typed confirmation and an export offer.
- Session handling on upgrade: the deployment keeps `obol_sessions` as the only session registry. Session rows written before 0.4.0 without a `createdAt` receive no guessed age, so those devices sign in again once.
- Zero-total invoices are accepted ([D018](../decisions/D018-zero-total-invoices.md)). Migration `1700000022_allow_zero_invoice_total.js` relaxes `invoices.total_amount` to `required: false`, because PocketBase treats the number `0` as blank for a required numeric field and rejected a card period with no purchases. Use cases still write a number; only the PocketBase blank check is removed. Rollback restores the constraint only when no invoice carries a null or zero total.
- Deterministic sessions migration ([D017](../decisions/D017-deterministic-sessions-migration.md)). Migration `1700000011_create_sessions_collection.js` now saves only a bare `sessions` base collection with no fields and no indexes, and `1700000017` adds `userId`, `expiresAt`, `deviceLabel` and `idx_sessions_expiresAt`, which is the schema every successfully migrated deployment already has. Before this change 5 of 30 fresh volumes failed with `no such column: expiresAt`, rolled back the batch and exited; 40 of 40 fresh volumes now migrate to the same schema. Deployments that already recorded 0011 never re-run it.
- Self-hosting runs on the pinned image `ghcr.io/muchobien/pocketbase:0.40.6@sha256:9a0be68a80ca1348ba8d15f217b3f983be4c094b3c571a09b3ebdeb357259338`. Release 0.4.0 adds migrations `1700000018` through `1700000021` (sync metadata, operation journal, station state, snapshot import receipts), `1700000022` (zero-total invoices), `1700000023` (recurrence category) and `1700000024` (finance audit dates). All are additive and none delete financial data.

## Operator upgrade

Back up the PocketBase volume first, then pull the checkout and recreate the containers. Migrations ship in the checkout and apply when `obol-pb` starts.

```bash
cd /path/to/repo
docker compose -f docker-compose.self-hosted.yml --env-file .env.self-hosted stop
docker volume ls   # confirm obol-self-hosted_obol_pb_data
docker run --rm -v obol-self-hosted_obol_pb_data:/data:ro -v "$PWD":/backup alpine \
  tar czf /backup/obol_pb_data-$(date +%F-%H%M).tgz -C /data .
docker compose -f docker-compose.self-hosted.yml --env-file .env.self-hosted start
```

Copy the archive off-host before continuing. The upgrade itself is:

```bash
cd /path/to/repo
git pull
docker compose -f docker-compose.self-hosted.yml --env-file .env.self-hosted build obol-bff obol-web
docker compose -f docker-compose.self-hosted.yml --env-file .env.self-hosted up -d
docker compose -f docker-compose.self-hosted.yml --env-file .env.self-hosted logs -f obol-pb obol-bff obol-web
```

Take the volume backup before `git pull`, not after. Verify with `curl http://127.0.0.1:8080/` returning `{"status":"Online"}`, the `obol-pb` log showing migrations `0018` through `0024` applied in order, and the web client answering through the TLS proxy.

The full runbook, including backup commands and the migration list, is [self-hosting.md](../self-hosting.md). The iOS upload path is unchanged: `npm run ios:testflight` with `MARKETING_VERSION` at `0.4.0`, see [ios-testflight.md](../ios-testflight.md).

## Operating constraints

- One live BFF process per deployment. The D016 mutation gate serializes writes in a single process, so do not scale `obol-bff` and do not run a second copy against the same PocketBase. This is a 0.4.0 rule from [D016](../decisions/D016-native-offline-sync.md), not a D009 session rule.
- The operation journal is not compacted in 0.4.0. Retention is unbounded by design for one owner at personal scale; compacting it needs a later decision with a station-cursor protocol.
- Conflicts are explicit. A rejected operation surfaces the wire cause to the user and is never silently rebased or merged; two legitimate equal payments both survive an import.
- Clients ignore unknown response fields. The server may add optional response fields; a client must not add fields the server does not know.
- The macOS cask entry in this checkout is regenerated from the published 0.4.0 manifest by the release workflow. Until that commit lands, its `sha256` still describes the 0.2.0a zips.

## Scope limits

- One owner per deployment. Every valid session sees the same data; multi-user sharing and per-record ownership are not included.
- Central hosting remains self-managed. Obol does not operate a hosted service.
- Moving an installed release candidate to the stable channel is still a manual install.
- Windows setup packages remain unsigned; macOS builds are signed ad hoc and the cask clears the quarantine attribute on install.
- Managed data restore, journal compaction and multi-process BFF deployment stay out of scope for 0.4.0 and require their own decisions.
