# Obol 0.4.5

This release adds a second recurrence cadence: monthly rules keep their day-of-month anchor, and a rule can now be weekly on a chosen ISO weekday. The cadence is implemented once per layer — server use cases, the desktop station, the native iOS engine and the parity fixtures consumed by both engines — and it is additive, so every existing recurrence keeps behaving exactly as it does in 0.4.0.

## Included

- Weekly recurrences ([D019](../decisions/D019-weekly-recurrences.md), canon [§3](../canon.md), [§6](../canon.md), [§7](../canon.md)). Two optional columns on `recurrences`: `frequency` (`monthly` or `weekly`, absent means monthly) and `weekday` (ISO 1 to 7, Monday first). `payday` is not reinterpreted; it stays the monthly anchor.
- Weeks are UTC ISO weeks. The cron materializes the current week's occurrence, the manual launch targets the next week, and a pause never backfills missed weeks. A weekly date is exact, so no clamping applies.
- Occurrence identity is the date: `skipped_periods` keeps one JSON array whose monthly entries stay `YYYY-MM` and whose weekly entries are the occurrence day `YYYY-MM-DD`. Idempotency matches the child on that day, so two runs of the same week never duplicate a fact.
- Weekly card recurrences work. Each occurrence is priced into the invoice that covers it, so a monthly invoice carries four or five weekly lines, and the invoice projection shows them without double-counting.
- Title format for a weekly child is `<name> - <YYYY-MM-DD>`, or `<name> - Parcela <n>/<N>` when the rule has `total_installments`.
- Web and desktop recurrence modal: cadence select, weekday select shown only for weekly rules, `payday` shown only for monthly rules. The recurrence list and details show `Mensal — dia N` or `Semanal — <weekday>` instead of a bare day number.
- Native iOS: recurrence model, `FinanceEngine`, `ForecastEngine` and the outbox payloads carry the cadence; the editor has the same cadence and weekday controls, and the list shows the cadence label.
- Sync contract unchanged: `protocolVersion` stays 1, `frequency` and `weekday` are optional additive fields in the wire and snapshot validators, and `RECURRENCE_MONTH_EXISTS` keeps its code for both cadences.
- Migration `1700000025_add_recurrence_frequency.js` adds both columns. It is additive, idempotent, refuses a same-named incompatible field, and its rollback removes only those two columns.
- iOS build tooling ([E008](../epics/E008-tuist-and-weekly-recurrences-045.md), Track 1). The shared `App` scheme is committed, the empty `app/ios/debug.xcconfig` and its project wirings are gone, `app/context.md` documents the native project, and `.github/workflows/ios-swift-test.yml` runs `xcodebuild -list` plus the 78-test Swift parity suite on every change under `app/ios`. Tuist adoption stays deferred: the project has one target, one scheme and synchronized folders, so a generator would cost 18 to 24 hours and buy nothing today.

## Operator upgrade

Migrations ship in the checkout and apply when `obol-pb` starts. Back up the PocketBase volume first, then pull and recreate:

```bash
cd /path/to/repo
docker compose -f docker-compose.self-hosted.yml --env-file .env.self-hosted stop
docker run --rm -v obol-self-hosted_obol_pb_data:/data:ro -v "$PWD":/backup alpine \
  tar czf /backup/obol_pb_data-$(date +%F-%H%M).tgz -C /data .
git pull
docker compose -f docker-compose.self-hosted.yml --env-file .env.self-hosted build obol-bff obol-web
docker compose -f docker-compose.self-hosted.yml --env-file .env.self-hosted up -d
docker compose -f docker-compose.self-hosted.yml --env-file .env.self-hosted logs -f obol-pb obol-bff obol-web
```

The `obol-pb` log must show `1700000025_add_recurrence_frequency.js` applied after `0024`. No data migration runs: existing recurrences read as monthly. Copy the archive off-host before continuing.

iOS uploads use the same manual path, with `MARKETING_VERSION` at `0.4.5`: `cd app && npm run ios:testflight`, see [ios-testflight.md](../ios-testflight.md).

## Operating constraints

- One live BFF process per deployment, unchanged from 0.4.0. The mutation gate is in-process.
- Mixed versions are unsupported in the forward direction: a server that predates 0.4.5 rejects the new request and snapshot fields, so the server and both clients upgrade together. An older client that never sends the new fields still works against a 0.4.5 server, because both columns are optional.
- A cadence change never rewrites generated facts. Switching weekly to monthly cannot duplicate a month that already has a child; switching monthly to weekly may add weekly children inside the current month, which is the cadence the user asked for.
- The operation journal is still not compacted.

## Scope limits

- Monthly recurrences keep exactly the 0.4.0 dates, titles, invoice lines and error codes. The parity suite proves both cadences against the same fixtures.
- Weekly recurrences are not backfilled. A rule created mid-week starts with the current week's occurrence, and a paused rule resumes with the current week only.
- Tuist is not adopted in this release; the re-evaluation trigger from E008 stands.
